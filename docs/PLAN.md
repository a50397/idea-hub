## 5d. Departments combobox Enter-key fix — ✅ COMPLETE (2026-07-26, e2e-confirmed; awaiting user commit)

Root cause of the `departments.spec.ts` "admin sets a department notification email and it persists" flake: the edit dialog's notification-emails `<v-combobox>` sits inside `<v-form @submit.prevent="updateDepartment">`, and Vuetify's own Enter `preventDefault` is CONDITIONAL — skipped when the keydown reports `isComposing=true`, which `pressSequentially()`+Enter can produce — so Enter leaked to implicit form submission and saved+closed the dialog with the email uncommitted. Fix: unconditional `@keydown.enter.prevent` on that combobox (`DepartmentsPage.vue`); Vuetify still commits the chip imperatively. Two unit tests pin it (normal Enter and the `isComposing=true` reproduction: chip committed, `defaultPrevented`, no update call, dialog stays open). Gates: frontend tsc + vue-tsc + vitest 411 + i18n-smoke green. E2E confirmed clean 2026-07-26 with fresh servers + freshly dropped/seeded `ideahub_e2e`: **15/15 passed in 10.3s, 0 flaky, 0 retries** — the previously flaky test passed first-attempt. (Method note: never stress `departments.spec.ts` with `--repeat-each` under default parallel workers — the file is serial because its tests mutate one shared department set; parallel copies collide and produce false failures. Use `--workers=1` for stress runs.) Files: `frontend/src/pages/DepartmentsPage.vue`, `frontend/src/__tests__/DepartmentsPage.test.ts`.

**Follow-up (2026-07-26, user-approved & applied):** the same exposure existed in `SubmitIdeaPage.vue` — its tags `<v-combobox>` sits inside `<v-form @submit.prevent="handleSubmit">` which has a real `type="submit"` button, so a stray Enter on a pending tag could submit the whole idea. Same one-line `@keydown.enter.prevent` fix + two mirrored tests (normal Enter with a fully valid form proving create is NOT called, and the `isComposing=true` reproduction).
